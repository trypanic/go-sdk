## Consumer-visible v2 release notes

Use [the v2 migration table](../v2-api-migration.md) for exact old/new symbols.
These notes supplement release-please; CHANGELOG.md was not manually edited.

- Imports now use `github.com/trypanic/go-sdk/v2`. Package identifiers are
  `postgres` and `mongo`; `slices` becomes `batch`. Redundant/stuttering API
  names are removed, including HTTP/LLM types, PostgreSQL constructors,
  storage interfaces and `envs.NewLoader` (use `LoadInto` or `Load[T]`).
- OTLP is isolated in `logger/otlp`; base logger accepts `io.Writer` and no
  longer links gRPC. HTTP/LLM/Mongo/Hertz/messaging constructors expose concrete
  adapters, with consumer interfaces and documented `Unwrap`/`Engine`/`Database`
  escape hatches. Router contracts include PATCH/HEAD/OPTIONS/Handle. Mongo
  cursor/result interfaces expand. `algorithms.Backoff` is SDK-owned.
- gRPC requires transport credentials or explicit `WithInsecure`. Strict OTLP
  `NewProvider` defaults to TLS; lenient `InitProvider`/`Setup` remain compatible.
  LLM keys/endpoints and messaging topology are validated more strictly.
  Environment configuration is explicit; plain messaging no longer reads
  `RABBITMQ_TOPOLOGY_FILE`. Logging defaults to Prod when the environment is unset.
- Retryability also requires safe replay. Non-idempotent requests need an
  idempotency contract, demonstrably unsent original request, or explicit
  duplicate-side-effect opt-in. Redirect failures cannot make a delivered POST
  safe. HTTP/messaging use bounded full jitter, Retry-After and context budgets;
  messaging has an explicit 15-minute elapsed cap and per-key publish retry.
  RabbitMQ publishing uses confirms/mandatory returns; cancellation requeues
  in-flight deliveries and Close is terminal.
- HTTP response/error capture is bounded; trailing JSON data cannot evade the
  response limit. Bodies are omitted/redacted by default. URL userinfo/query
  values, nested diagnostics, URL-bearing headers and escaped JSON secret keys
  are sanitized. Raw-body capture remains an explicit development choice.
- `Public`/`PublicJSON`, HTTP replies and gRPC statuses avoid private diagnostics.
  Error codes/status/retryability are more specific across HTTP, LLM, PostgreSQL,
  Mongo, storage and messaging. `As`/`HasCode` handle wrapped/joined/typed-nil
  chains. Expected validation errors omit stacks while preserving metadata,
  identity and causes; invalid validator configuration remains stackful.
- Storage defaults to owner-only permissions, rejects invalid modes/keys,
  preserves foreign files on Clear, protects final paths against symlink races,
  and appends JSON Lines while reading the old array format and valid legacy
  keys. Directory-sync errors after rename do not undo the completed rename.
- Setup contexts bound initial network work without owning successful clients'
  lifetimes. Mongo adapters wrapping supplied driver clients borrow ownership.
  Logger initialization/publication and errorkit settings are synchronized.
  Tracing injection, failure status/sanitization and bounded span names are
  consistent; HTTP paths/LLM models are attributes, not span-name identifiers.
- Accepted behavior changes originally classified `auto` are explicit:
  `ERROR_KIT_MAX_STACK` uses strict integer parsing; `logger.Error(nil)` reports
  `ERR_UNKNOWN`; stack paths become module-relative; Hertz Shutdown observes
  its caller context and returns timeout instead of nil; unsupported methods
  return 405 correctly. Additional escaped-slash/opaque-URL and segmented-JSON
  corrections preserve their documented contracts.
