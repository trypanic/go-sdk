## Architecture and ownership choices

- OTLP lives only in logger/otlp. Base logger accepts io.Writer and shares
  context lookup through internal/logctx, avoiding a reverse exporter edge.
- Algorithms exposes Backoff while preserving its historical cenkalti schedule.
  HTTP and messaging share internal/backoff full jitter; their existing public
  configuration structs/units are retained. Randomness is for retry timing,
  not authentication or cryptography.
- Concrete HTTP/LLM/Mongo adapters store an instrumenter internally. Explicit
  decorators remain for interface composition and preserve nil identity.
  Wrapping an already traced adapter intentionally adds a second span.
- Mongo NewFromClient borrows the driver. Close on that adapter does not
  Disconnect it. Owned constructors retain cleanup responsibility.
- PostgreSQL and messaging context constructors bound network setup but do not
  let constructor cancellation terminate successfully created clients.
- Deferred Mongo FindOne Decode failures have a bounded child span. The result
  stores a SpanContext, not the full caller context, and the initial span ends
  when FindOne returns even if no Decode follows.
- Public fakes use explicit callbacks rather than embedding nil interfaces.
  Internal driver/AMQP seams stay private to avoid import cycles and exporting
  internal protocol details; an external telemetry fixture migrated to mongotest.
- Package `batch` avoids the standard-library slices collision while preserving
  Chunk's non-positive-size and clipped-capacity contract.
- Stackless expected validation errors preserve all non-stack error data.
  Single-run directional benchmark: failure 3632 → 341.7 ns/op,
  2537 → 376 B/op, 16 → 5 allocs/op. Success remained allocation-free.
  No statistical significance claim is made from these single runs.
